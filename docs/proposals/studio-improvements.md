## 0. In three lines

1. **Studio is well built and has no sprint surface at all.** `phases/activities.yaml` declares nothing for the Build phase, Studio calls none of `sprint.py`, `generate_sprint_report.py` or `track_decisions.py`, and a grep of `studio/` for "sprint" or "refine" finds nothing. The plugin side already provides everything a Sprint view needs (`sprint.py status --json` is a complete, read-only, exit-0 document).
2. **One defect disables every model-backed Studio feature on an older Claude Code.** Studio passes `--permission-prompts none`, a flag that exists in 2.1.289 (latest) but not in 2.1.239. There is no probe or fallback, and the test fake accepts any flag, so CI cannot see it. Fix: probe `claude --help` once and fall back to `--permission-mode dontAsk`.
3. **A handful of medium defects would bite a team daily**: Build can be signed off around the declare-complete flow; the installed `specs/spec-template.md` shows as a phantom board row and a Closing blocker; sign-off fails open when the gate script errors and can lose the previous phase layer; 28 call sites parse redacted stdout as JSON; sprint records are not on the sync allowlist.

## 2. Findings that drive the plan

| # | Finding | Severity | Evidence | Fix |
|---|---|---|---|---|
| F1 | `--permission-prompts none` is passed to every `claude` call; absent in Claude Code ≤ 2.1.239, present in 2.1.289 | **Critical** on older CLIs | `claudeAssist.ts:47-50` `CLAUDE_SHARED_SAFE_ARGS`, spread into `chatArgs.ts:142`, `agentRun.ts:72`, `drafts.ts:49`, `signOff.ts:157`; probe `claude --permission-prompts none -p </dev/null` → `unknown option` on 2.1.239; 2.1.289 `--help` lists both flags | **Built:** `CLAUDE_SHARED_SAFE_ARGS` is now `--permission-mode dontAsk --strict-mcp-config` (parses on both CLIs; `dontAsk` auto-denies anything not pre-approved — the old flag's intent), so no per-version branching of argv; `shared/claudeContract.ts` exports `REQUIRED_CLAUDE_FLAGS` (every flag Studio emits) and `parseHelpFlags()`; `tooling.ts` runs `claude --help` once per detected version (5 s timeout, via `runCommand`) and reports `missingFlags` on the Claude `ToolStatus`; Tooling / Settings render "Claude Code <ver> lacks <flags> — update with `claude update`" and model buttons are enabled only when nothing is missing; a zero-cost real-CLI contract test (`claude <args> -p </dev/null` → parse failure prints `unknown option`) |
| F2 | Plugin auto-detect drives the newest *cached marketplace* plugin (1.5.0 here), never the checkout Studio ships in | High | `tooling.ts:134-173`; README says the opposite | Prefer `<APP_ROOT>/../scripts` when unpackaged and it has `capabilities.py`; use `capabilities.py` as the marker; show plugin path + version in Settings and ToolingIssues |
| F3 | Build can be signed off through the generic SignOffPanel, bypassing `declare_complete.py` | High | `StageHome.tsx:133` (no stage check), `signOff.ts:181-219` | For `build`, show "Build ends from Closing" + link; `signOff.ts` refuses `build` |
| F4 | `specs/spec-template.md` (installed by the harness) is a board row and a Closing "unreadable spec" blocker | High | `spec_status.report_all:505`, `declare_complete._specs:55-75` glob every `specs/*.md`; `track_specs` and `sprint.py` already filter `^\d{4}-` | Apply the same filter in both; tests |
| F5 | Sprint records `.sdlc/sprints/SNN.md` are not on the sync allowlist (spec keys and the ledger are) | High for sprint users | `projectPaths.ts:26-46` | Add `/^\.sdlc\/sprints\/S\d{2,}\.md$/`; narrow layers to `*.md` so `.superseded-<date>` stays local |
| F6 | Sign-off fails open when `check_gates.py` errors; a failed re-sign-off can destroy the previous layer and push an unreviewed draft | Medium | `signOff.ts:50-59, 116-171` | Fail closed on non-zero exit without MUST lines; draft to a temp path, validate, swap, restore on failure |
| F7 | 28 sites parse the *redacted* stdout as JSON (`token:`, `auth:` in data get rewritten) | Medium | `commandRunner.ts:73` vs `readiness.ts`, `board.ts`, … | Use `rawStdout()`; a vitest lint fails on `JSON.parse(x.stdout)` |
| F8 | Allowlist checked before normalisation: `specs/../.git/config` passes | Medium | `projectPaths.ts:48-89` | Normalise and reject `..` first; tests |
| F9 | No single-flight between the 2-min pull, save, clash resolution, PR polling; chat turns not serialised | Medium | `index.ts:127-136`, `sync.ts`, `chat.ts` | Per-project async mutex (`locks.ts`); timer skips a tick while held |
| F10 | Board: dead "group by epic", status filter lacks `deferred`, "Nothing is waiting on you" when signed out, rows lack sprint fields | Medium / Low | `BuildBoard.tsx:147-153`, `boardModel.ts:62`, `spec_status._spec_row` | Group by **sprint** (rows gain `sprint`, `next_owner`, `eng_review`, `data_review`, `depends_on`), add `deferred`, honest signed-out state, `needsMe` counts `next_owner == me` |
| F11 | Activity panels crammed into a 288 px column; declared Build activities would sit under Build › Documents | Medium | `WorkflowTab.tsx:56`, `nav.ts` | **Absorbed by Observatory** (`studio-observatory.md` §7 WorkflowTab: `FocusedActivityHost` renders the picked activity in the main slot); the `Sprint` entry in `BUILD_VIEWS` shipped in Batch 2 |
| F12 | One malformed `activities.yaml` entry blanks every stage; unknown keys vanish silently | Medium | `activities_model.py:106`, `stage_readiness.declared_activities` | **Built (part):** `validate()` never raises; `ACTIVITY_KEYS` rejects unknown keys and every field is type-checked, each problem a `phase <p> / activity <id>: …` string; `stage_readiness.declared_activities()` also catches any other exception as a warning. **Still open:** only the FIRST problem is surfaced and it blanks every stage's list — per-phase warnings deferred to Batch 4 |

## 4. Decisions for you

| # | Decision | Recommended | Alternative |
|---|---|---|---|
| D1 | CLI flag strategy | **Taken (built):** emit `--permission-mode dontAsk` on every CLI (present in both 2.1.239 and 2.1.289, same intent), and probe `claude --help` only to *report* missing flags — no argv branching to keep in sync | Prefer `--permission-prompts none` when present with a fallback (rejected: two argv shapes for one behaviour); or hard-require ≥ 2.1.289 |
| D2 | Where the Sprint view lives | A `Sprint` entry beside Board in the Build sidebar group, plus the Build › Workflow panel | Panel only (one level down) |
| D3 | Board grouping | Replace the dead "epic" grouping with "sprint" | Keep epic, add sprint |
| D4 | Soft-require `gh` / `claude` to open a project | **Built as a code-host provider** (`docs/proposals/code-host-providers.md`): a provider is resolved per repository from its `origin` remote, and Studio soft-requires the *detected* host's CLI — `gh` on GitHub, `az` on Azure DevOps — with a per-feature disabled reason from one helper; neither CLI can block opening a project, and the one the repository does not use reads "not needed for this project" | Keep hard requirement |
| D5 | Write verbs from Studio (Batch 3) | Yes, verdict / next-action / ack / ready / close; `--by` = the signed-in account resolved through the roster on both hosts (GitHub login → `@handle`; Azure DevOps UPN → the roster entry whose `email:` matches, else the UPN itself). The main process computes it, never the renderer; when the host cannot say who is signed in (PAT-only `az`) a typed name is allowed only in that state and recorded as `accountSource: typed` | Read-only Studio for sprints |
