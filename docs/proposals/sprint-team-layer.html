Sprint Team Layer — what it looks like

Two new commands. /sdlc-sprint slates a set number of specs into a two-week sprint by a mix of work and readies it. /sdlc-refine refines that sprint's specs. Nothing about the phases or the gates changes.
A sprint is a commitment window laid over the spec backlog — never a second backlog, never a gate, never a velocity chart. ADO stays manual.

.sdlc/reports/sprint-S07-planning.html

Self-contained HTML in the style of the phase reports, linked from reports/index.html. Run the planning meeting from it:

  • Header — goal, dates, board reference, readied by
  • Commitment — the slate with risk, type, DoR, Eng and Data verdicts, next owner
  • Mix and capacity — mix vs target, WIP cap, turnaround target or "no target set"
  • Build order and next up — with dependency arrows and why
  • Spec cards — Goal, Why, acceptance-check count, tier and why, harness context, open Decision List items
  • Open decisions and carried-in specs with their reasons
  • Footer — "Never tracked: velocity, story points, PR count, lines of code."

The same renderer writes sprint-S07-review.html at close.

Nothing locks — the guarantees
any phase

Refine whenever specs exist

Neither command reads the engagement phase to decide whether it may run. Mid-Build refinement for the next sprint is the normal case.

no going backwards

Upstream fixes stay in place

A spec whose gap is in a Phase 1 or 2 artifact runs /sdlc-refine --upstream: edit the artifact in place (human-confirmed diff), record it, re-gate that phase with check_gates.py --phase N as information, regenerate that phase's layer, return to refinement. Changing earlier-phase artifacts during refinement is the normal case. current_phase never moves; layers are living summaries, not locks.

never a gate

Sprints are advisory

ready and close check only the slate. Nothing is written to state.yaml; the seven gates neither block a sprint nor are blocked by one.

human exit

Leaving Build is unchanged

Still a human declaration. /sdlc-next shows one line about the last sprint's outcome; close never suggests advancing.

Five things we add regardless
R1

Handoffs with ack

handoff --to and ack. A spec waiting between teams always has an owner and an age. "Never rely on the next owner noticing."

R2

Eng + Data verdicts in "ready"

Independent validation, in parallel, before anyone builds. This is what readying a sprint means for this team.

R3

Self-rendering agenda

/sdlc-refine with no arguments: not-ready specs and why, pending verdicts by age, overdue decisions. The Mon/Wed/Fri review reads it.

R4

Honest close, no velocity

Kept / carried / dropped with reasons, this sprint only. Points, estimates, hours and per-person counts are refused at the ledger. Fix the retro template's velocity row now.

R5

Sprint at session start

One [SDLC-SPRINT] line in both hook shells; the stale section-plan summary the Build hook still prints is retired at the same time.
