## §0 — In five lines

1. **What it is:** the Electron app reorganises around the Build loop — one sprint home (lanes · Today · planning · spec card · close) with the lifecycle as context — and every number, order, state and refusal on it is a plugin field shown verbatim.
2. **The shell:** the sidebar retires; a top band (mark · omnibar trigger · needs-you chip · sync · overflow menu) and an SVG **lifecycle strip** (nine stations, lit rail, the Build station reading "Build Loop · S08 · 8th sprint") replace it; two homes, chosen per open by `homeFor()`.
3. **The truth rule:** the renderer never spawns, never joins across sources and never derives — main assembles one `CommandCenter` read model with per-block provenance and runs every write through a closed argv table with the signed-in person as `--by`; exit 0 "Done", 1 "Not done", 2 "Refused by the plugin", stdout/stderr verbatim.
4. **The plugin grows additively:** `sprint.py list | log | carry | edit`, `spec_transition.py confirm-tier | assign`, `handoff.py --check`, `spec_readiness.py --all` + `ladder[]`, `record_findings.py report --json` + `findings[] recurrence{} [--spec]`, `spec_status.py` row + `deferred_reason`, ten `capabilities.py` entries — existing text, exit codes and goldens byte-identical; the protected core untouched (pytest + `git status --porcelain` prove it).
5. **The build:** P0 contracts → P1–P7 in parallel with disjoint file ownership → P8 integration (capture v11, guide, README, CHANGELOG); lands on `feat/togo-overhaul`, fast-forwards into `feat/studio-improvements` so PR #1 carries it.

## §1 — The shell decision

**Two homes, one pure choice.** `homeFor(status, sprintProbe, capabilities)` in `studio/shared/nav.ts` returns `'sprint'` iff `status.current_phase.id === 'build'` and `capabilities` includes `sprint-status`; otherwise `'lifecycle'`. A Build-loop project with no sprint yet still lands on the sprint home, in its empty state (the loop is the work; `sprint.py status` has `has_data:false`, so the header shows the plugin's own `note`). A plugin lacking `sprint-status` lands on the lifecycle home and the Build station carries "sprint home arrives with a newer plugin: lacks sprint-status". The choice runs once per project open (today's three `setArea('documents')` sites in `App.tsx`), never on a timer. Explicit switching: the strip (mouse), `g s` sprint home, `g l` lifecycle home; the old `g b/h/c/d` keep working as Build views.

**What replaces the sidebar.** Top to bottom: (1) **TopBand** — the SDLC Studio mark + project name as one `<button>` (leans out to the lifecycle home); the **omnibar trigger**, a `<button>` styled as a field reading "⌘K · a spec id, a verb, or a place" (never an `<input>` at rest — the palette overlay owns the input while open, exactly as today's Search button); the **needs-you chip** (the length of the addressed list, §2.4); `SyncChip`; an overflow `…` menu. (2) **LifecycleStrip** — the **first `<aside>`** in DOM order, holding `<nav aria-label="Project">`: nine SVG stations in registry order from `spineModel` (`stationU`, `railProgress`, `STAGE_SHORT_LABEL`, `nodeKind`), lit rail = signed-off count, the viewed station carrying `data-viewing` (never `aria-current`), the current station pulsing (the one sanctioned idle motion, `full` familiarity tier only). The Build station's accessible name starts **"Build Loop"** (the `openBuildView` helpers in `sprint.spec`, `board.spec`, `constellation.spec` match `/^Build Loop/`) and reads "Build Loop · S08 · 8th sprint" when `sprint.py list --json` reports the ordinal, "Build Loop · S08" otherwise, "Build Loop" with no sprint. It expands on click/Enter (`aria-expanded`, never hover) to the five `BUILD_VIEWS` — `sprint` relabelled **Home**, then Board, How it is going, Closing, Documents. Exactly one `aria-current="page"` on the station or view that owns the showing screen (`activeNav` keeps deciding). (3) `<main id="main">` renders the home as its only child. The chat stays the **second `<aside>`** at 380 px; the console stays the bottom drawer. So `a11y.spec:76` (two asides, sidebar-then-chat) stays green **verbatim** — the strip takes the sidebar's seat; only `sidebar.test.ts` / `sidebarFade.test.tsx` are re-recorded as `lifecycleStrip.test.tsx` (§8).

**Where the rest lives.** Overflow menu: Settings (⌘,), Appearance (Settings anchor), Console (⌘J), Chat (⌘\), Shortcuts (?), Steering mode (`g t`), New project / Open folder. All six remain palette actions too. Settings, Console, Appearance, Chat, `DocumentView` editing, `SignOffPanel`, `PipelineEvidencePanel`, `HandoffDialog`, Gate auth and `FeatureCompleteScreen` are kept byte-for-byte and reached from the strip or the menu.

## §2 — The read model and the verbs

### 2.1 One identity, resolved once

`studio/electron/main/actor.ts` `resolveActor(projectPath) → { name, source: 'roster'|'host'|'typed' } | null`, from `ConnectionInfo` (`rosterHandle` → `account` → typed name per `typedActor.ts`, which already refuses AI-looking names). Every `--by`/`--to`/`--developer`/`--owner` is filled **here**; the renderer never assembles one. No actor → every write IPC refuses before spawning with `reasons.NO_ACTOR` ("Sign in or type your name — the plugin records who is accountable") and the dialog opens `TypedActorForm`. Renderer-side matching ("you" ring, Mine filter, needs-you) uses one module, `studio/shared/identity.ts` (`samePerson` moves here from `boardModel.ts`, which re-exports it). Azure UPNs that map to no roster entry read "unmapped" (`references/team-model.md`).

### 2.2 Read IPC (all P-class: reads only, never pull/sync)

| IPC (`window.studio.*`) | Runs (main) | Returns |
|---|---|---|
| `getCommandCenter(projectPath)` | fan-out, parallel: `sprint.py status --json`, `sprint.py list --json`, `spec_status.py --all --json` + `track_specs.py --json`, `track_decisions.py --json`, `record_findings.py report --json`, `scorecard.py report --json`, `project_settings.py --json`, `sprint.py log --since <D> --json` | `CommandCenter` (§2.3) |
| `getSlateProposal(projectPath, sprintId)` | `sprint.py slate --sprint SNN --json` (no `--spec` = read-only proposal) | `SlateProposal` = the plugin's keys camel-cased + `hasData`, `note` |
| `getSpecCard(projectPath, specPath, developer?)` | `spec_readiness.py --spec --json` (with `ladder`), `spec_status.py --spec --json`, `record_findings.py report --json --spec PATH`, `check_channel.py --json` when `channel:` set, `handoff.py --check --developer` when a developer is named | `SpecCard{ readiness, ladder[], status, findings, channel|null, handoffCheck|null }`, each block `SourcedBlock` |

Existing reads stay: `getSprintStatus`, `getBoard`, `getSpecReadiness`, `getSpecStatus`, `getScorecard`, `getProjectSettings`, `getConnectionInfo`, `renderSprintReport`, `openReport`, `getChatState`.

### 2.3 `CommandCenter` — one document, every block sourced

`SourcedBlock<T> = { source: string; fetchedAt: string; ok: boolean; data: T | null; error: string | null }` — `source` is the literal "`<script> <verb> --json`" the element shows as provenance; `data:null` renders "no data", never 0. Blocks: `sprint` (`SprintView`), `sprints` (`{ sprints[{id,state,goal,start,end,ordinal}], active, count }`), `board` (`Board`; `track_specs` exit 1 is a WIP *finding* → `ok:true` + `warnings[]`), `decisions`, `findings` (`{tracked, openDebt, fixedClaimMismatches, findings[], recurrence}`), `scorecard`, `roster`, `log` (`{ events[], count, since, exists, skipped }`), plus two lists main **derives by exact handle match only**: `needsYou: NeedsYouItem[]` (`{ kind: 'ack'|'review'|'decide'|'confirm-tier', spec?, id?, action, source }` — hand-offs whose `to` is me, PRs whose `waitingOnHandle` is me, open decisions whose `owner` is me (overdue first), specs I own with `risk` set and no `risk_confirmed_by` *only when* `confirm-tier` is a capability) and `sinceYesterday: StreamRow[]` (`log.events` verbatim + board rows with `pullRequest.mergedAt` in the window + decisions in `CLOSED_STATUSES`, each row tagged `origin`, ordered by the timestamp the source gave, undated rows last and labelled "undated"). `verdicts_pending` has a lane, not a person — those render under "Team is waiting on", never as "yours". The window is a filter the person picks (1 / 3 business days; main passes `--since`), never a reported number. **No per-person key exists anywhere in this type.** Cache: one per project, keyed by block; local blocks invalidated by any write IPC, by `onSyncState` pull completion and by "Refresh this screen"; the host block (`spec_status --all`) keeps a 60 s TTL and its own `fetchedAt` ("as of 10:42"). **No `fs.watch`, no background polling of `gh`/`az`.**

After any exit 0 the renderer re-runs the P-class reads it already holds — **never before**: no card moves, chip changes or counter ticks until the exit code *and* the refreshed read have both arrived.

## §9 — For the owner, in plain words

1. Opening a Build-loop project lands you on the sprint, not on a document list: four lanes that *are* the loop, a Today column that says what needs you, and who holds what.
2. The sidebar is gone. A thin strip of the nine stages sits across the top; the Build station names the sprint; click a station to lean into its documents, decisions and sign-offs.
3. ⌘K takes plain words — "verdict 0002 accepted", "hand 0006 to Sam", "defer 0003 to S08 because …" — shows you exactly what the plugin will run, and shows you exactly what it answered.
4. Nothing on screen is SDLC Studio's opinion: every number, order, wait and refusal is a plugin field, named, and "no data" stays "no data".
5. The plugin learns a few new verbs (list, log, carry, edit, confirm-tier, assign, a hand-off dry run) — all additive, all tested; the protected core does not change by a byte.
6. Planning is a screen: refined backlog, the slate in the plugin's build order, what the plugin says, the plugin's proposal, one Commit that opens the planning page and a decision clock per unconfirmed tier.
7. The spec card shows the IDD loop whole — DoR gaps, the checking ladder coloured by the code host, the findings ledger — and the Hand off button says, in the plugin's words, why it is not yet allowed.
8. Closing a sprint is a screen too, and steering mode is a read-only view of the standard's numbers for the committee — no velocity, points or PR counts, ever.
9. Where a verb does not exist yet (security signer, standup notes, promote a finding) the control is there, disabled, and tells you why.
10. One build, eight packages with no two hands on one file, every pinned test green or changed with evidence, screenshots v11 beside v10 — landing on `feat/togo-overhaul` and into the same PR.
